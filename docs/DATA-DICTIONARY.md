# 潮窗字段

id保持字符串。kind取tide、ship、pilot、block、leg。start/end带时区；统一UTC秒。tide的value为潮高；ship为吃水；leg的value为海图水深；m/cm统一为m。ship的aux为通航分钟（申请占用时长）。leg的length_m为航段长度（米）、limit_kn为该段限速（节），仅leg记录使用。version为递增版本，采用同ID最高版；同版多条隔离。潮位乱序按时间排序。

基准水深8m，安全余量1m，要求潮高>=吃水+1-8（无leg记录时的旧口径）。相邻潮位最长允许3小时插值；缺口不外推。航道区间为半开，结束同刻可开始下一航次。引航窗口须覆盖整个航次。排程按最早申请时间、船舶ID确定先后，采用最早可行窗。并非全局最优调度。

业务ID按kind命名空间隔离。同一UTC时刻的潮位不同值全部隔离为TIDE_TIME_CONFLICT，不能用其中任意值开启安全窗；同值重复仅保留编号最小者。

冲突潮位时刻保留为插值断点，相邻有效观测不能跨越该时刻推算安全窗。

# 分段进港口径

有 leg 记录时，按分段方案核算，旧的整体潮窗只作参考。

- 航段顺序：按记录来源行号。外航道在前、内航道在后。
- 船体下沉：`squat = 0.008 * 航速^2`（m，航速单位节）。限速越高、航速越大，下沉越多。
- 需求水深：`吃水 + squat + 安全余量1m`。
- 可用水深：`该段海图水深 + 该段段内最低潮位`。
- 实际富余：`可用 - 需求`，取该段段内最紧时刻；段内任意时刻不得为负。
- 段速：限速内从高到低试算（0.5节步长，最低3节），取仍满足富余>=0的最大航速。
- 起航：申请窗、引航窗、封航、测深有效期与已占道约束下的最早可行时刻，按1分钟步长搜索。
- 只看每段进段时刻潮位的做法会低估段末落潮，作为“未采用方案 ENTRY_ONLY”留档并给出该口径下的最小富余。
- 整程按最浅段+最大下沉量一刀切的做法作为“未采用方案 GLOBAL_CONSERVATIVE”留档；它常错过实际可用窗口。

# 测深版本与失效

- 航道测深由 leg 记录的 `value`（海图水深）与 `version` 共同决定，构成批次测深基线。
- 同批航次（船号+申请窗相同）提交新版本方案时，旧批次的富余作废，标记 `DEPTH_UPDATED`，其占道登记同时释放。
- 提交版本回退的旧测深时，该批次保留可查但标记 `DEPTH_STALE`，不占道、不挤掉现行方案。
- 失效批次不能复核通过，接口返回 409 `SUPERSEDED`。

# 占道与幂等

- 批次ID由规则版本与输入内容摘要确定；同一内容重跑复用同一批次，不重复占道。
- 占道登记按批次覆盖写入：同批重跑或重放不会叠加。
- 复核“退回”释放该批占道；“通过”保留。
- 计算或写入失败时，旧批次与其占道登记原样保留（单事务写入）。
